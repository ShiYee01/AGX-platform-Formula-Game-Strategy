# V5 实战复盘与下一版改进方案

日期：2026-11-19。数据来自平台**公开回放**：最近21场本人正赛（11-17 16:09 至 11-19 08:16），每场10辆车的24Hz完整遥测，共约379万个有效车辆帧。复现方法见 `tools/replay_analysis.py`。

## 0. 结论

1. **掉排名的主要原因是车太慢，不是撞车。** V5同一场的最佳正赛圈比冠军慢34%–62%（Parkland中位数184s对108s，Highland 219s对157s，Crossover 193s对139s）。21场里19场只跑了3圈，平均名次6.1；能排到2–4名的场次，基本都是因为前面有车损坏退赛。
2. **V5只用了车辆约40–50%的能力。** 在同一湿度和速度区间对比全部车辆的实测：

   | 指标（干地，30–60m/s） | 全场能达到 | V5实际 | V5利用率 |
   |---|---:|---:|---:|
   | 横向加速度（过弯） | ≈2.5g | ≈1.1g | 44% |
   | 制动减速度 | ≈2.6–3.0g | ≈0.6g | 20–25% |
   | 最高速度 | 300–340km/h | 216km/h（代码上限） | — |
   | 全油门时间 | 冠军30–70% | ≈0% | — |

   全湿（湿度>0.8）时全场横向约1.4–1.8g，V5约0.7g，利用率同样约50%。
3. **时间损失均匀分布在弯中、制动区和直道**，不是某一个参数的问题。以Parkland（11-18 22:12）为例，单圈落后32s：弯中9.6s，入弯前150m制动区10.3s，直道12.3s。冠军单圈约30%的时间高于216km/h。
4. **能量和空气动力模式完全没用上。** 冠军会在制动时用ERS 0回收、在直道用ERS 2/3部署，SOC用到1MJ左右，并在直道开低阻模式（aero_mode=1）14%–49%的时间。V5几乎一直是ERS 1、aero 0，SOC停在3–4MJ没用。
5. **燃油多带了约45kg。** 冠军一般带7–20kg跑完4圈（每圈约1.2–1.4kg），V5带60kg，结束时还剩57–58kg。
6. **新增的“让道/防撞”不是当前瓶颈。** 21场里本人只记录24条contact，没有因damage退赛；可靠性已经够了，下一步应该把余量换成速度。

## 1. 数据来源与口径

- 平台公开接口，无需登录：`/competitions/{id}/history` 给出每场的参赛名、名次和故障；`/recordings/{job_id}/{static|events|frames}` 给出全部车辆的遥测、设计摘要和事件。
- 我们的席位从历史参赛名中按显示名匹配。本地第19、20文件夹的job_id和席位与历史记录对得上，说明匹配方法正确。
- 回放里本人的设计（60kg油、40kg配重）与仓库 `design.json` 一致。不过**没有training.jsonl，就无法逐帧核对这21场是否全部由V5源码驱动**。若想严格确认版本，请提供第21–30文件夹日志。
- 回放是观赛资料，只用于**离线标定车辆能力**，不进入 `act()` 的输入。这和平台文档“全知回放可用于核对环境”的说法一致。至于是否要模仿某位同学的具体行车线，建议对照课程规则再决定；本方案只使用全场统计出的物理上限。
- “全场能达到”取99.5分位数，样本里也包括后来撞车的车。所以它是物理上限，不是安全目标；下文的建议值都在它之下留了余量。

## 3. 弯道逐个对比（全部清洁正赛圈的中位数最低速度）

完整输出可用 `python tools/replay_analysis.py corners` 复现。半径为中心线最小半径；冠军走更宽的行车线，实际半径更大。

- **Parkland**：每个弯冠军快17–61km/h。例如3034–3076m（R26.5）我42对冠军93km/h，4188–4336m（R31）44对105km/h。
- **Highland**：快11–67km/h。两个发卡弯（210–252m、6565–6667m）只差11–15km/h，**差距主要在中高速弯**：例如892–906m（R142）119对182，1112–1142m（R115）107对174。
- **Crossover**：快10–32km/h。

可见V5在中高速弯过于保守，原因是 `lateral_budget` 为10–12m/s²（约1.0–1.2g）并乘以湿度系数，而实际可用约2.5g。湿度对抓地的缩放（全湿×0.55）与全场实测（1.4/2.5≈0.56）吻合，**这个系数是对的，问题出在基数**。

## 4. 代码瓶颈与修改建议（按收益排序）

### P0：把限速参数从“保守猜测”改成“实测上限的一定比例”

| 位置 | 现值 | 实测上限 | 建议第一步（约70%） | 第二步（约80–85%） |
|---|---|---|---|---|
| `lateral_budget` | 10/11/12 m/s² | ≈24.5m/s²（2.5g） | 17 m/s² | 20 m/s² |
| `BRAKING_BUDGET` | 5.5 m/s² | ≈25–29m/s² | 14 m/s² | 18 m/s² |
| `TOP_SPEED` | 60 m/s | ≈92m/s | 90 m/s | 90 m/s |
| `pedals()` 正加速度上限 | 5×grip（V5条件放宽到10） | 由功率决定，约1.0–1.5g | 稳定直线时直接给全油门 | 同左 |
| `pedals()` 制动下限 `-8×grip` | 7.8m/s² | 见上 | 与 `BRAKING_BUDGET` 联动 | 同左 |

几点说明：

- 三处要一起改。只放宽弯速而不加大制动，车会冲进弯里；只提高最高速度也没用，因为直道末端仍按5.5m/s²提前很早刹车。
- 速度规划和横向/制动预算都基于同一份 `grip_budget`，所以湿地会自动按比例降低，不需要另外设湿地参数。
- 全场高速段（60m/s以上）的可用横向加速度反而更高（有下压力）。下一步可以让 `lateral_budget` 随速度略增，但第一步先不加。
- `pedals()` 现在把加速度换算成“恰好够用”的部分油门，所以加速段油门中位数只有20–35%。建议：当目标速度比当前高2m/s以上、车稳定、直线时，油门直接给1.0，只在后轮滑动时限制。
- 按粗略的质点模型（只用中心线，没有行车线，比实战偏乐观），利用率从约42%提到60–75%时，单圈时间大致可以接近冠军水平。这只是方向性估计，不是圈速承诺。

### P1：能量与低阻模式（ERS / aero）

从回放推断的模式效果（由数据推出，平台文档没有明说）：

| ers_mode | 全油门时 | 制动时 |
|---|---|---|
| 0 | 不部署 | 强回收约 −320kW |
| 1 | 不部署 | 弱回收约 −50kW |
| 2 | 部署约 +175kW | 回收约 −210kW |
| 3 | 部署约 +350kW | 仍在部署（浪费） |

aero_mode=1：在70–80m/s时阻力降约20%，下压力降约41%。冠军只在直道、低横向负荷时使用（使用时|g_lat|的90分位只有0.35g）。

建议规则：

- 制动或滑行时用ERS 0（最大回收）；全油门且SOC>1.0MJ时用ERS 3，SOC在0.6–1.0MJ时用ERS 2，弯中用1或2。每圈回收上限为8.5MJ（赛道数据 `recharge_limit_mj`）。
- 前方约200m的曲率都低于0.002、未在制动、|g_lat|<0.3g时开aero 1；接近制动点或入弯前提前关回0。

### P1：车辆设计（独立做一次A/B）

- `fuel_load_kg`：60 → **约14kg**。按冠军实测每圈1.2–1.4kg，4圈（Highland更长）再留余量。从回放看，排位和正赛起步时油量都等于设计值（正赛会重新加满到设计值），所以排位用油不影响正赛。
- **必须同时修改代码中的低油量保护**：`fuel_kg < 5` 时限速27m/s、油门≤0.65。带14kg时最后一圈会触发它。改成按剩余距离估计所需油量后再保护，或把阈值降到约1kg。
- `ballast_kg` 40 → 20：前三名里约三分之一用20kg。属于小收益，不着急。
- 翼角、齿比、刹车比例：前三名绝大多数与默认设计相同，暂时不必改。

### P2：行车线

冠军在急弯会向弯心切1–4m（入弯前在外侧），V5基本沿中心线行驶（|n|中位数小于0.6m）。在已有的 `offset` 机制上，可以离线为每张地图生成一条平滑的最优横向偏移表（像地图曲率一样嵌入代码），让 `road_plan`/`steer_command` 跟随它。收益明显，但改动和风险都比P0大，建议P0验证后再做。

### P3：交通逻辑

车速提上来以后，被套圈的情况会大幅减少，超车会变多。V5里“起步380m内不超车、2.8m间距、前车150m内须为直道”这些超车条件偏严，可在P0稳定后再放宽。

## 5. 推荐的新方法

1. **用公开回放当“老师”，自动化每轮复盘。** 不需要登录，每场有10辆车完整遥测，信息量远大于只看自己的training.jsonl。`tools/replay_analysis.py` 已实现：拉历史 → 下载本人最近N场 → 对比冠军（概况、全场能力包络、逐弯最低速、单圈时间拆分）。一个人迭代时，这能省下大部分手动分析时间。
2. **从全场遥测标定一个更可信的本地模拟器。** 用379万帧拟合“抓地力（随湿度、速度/下压力变化）、制动、功率曲线、ERS模式效果、燃油消耗”，再离线优化每张地图的速度表与行车线，用未参与拟合的新对局检验。这比仓库里“质点模型+手选系数”更接近平台。
3. **小步迭代，用公开名次做A/B。** 每次只改一组（P0 → ERS/aero → 设计 → 行车线），每版跑够约6场（三图各2场），按同图、同湿度区间比较最佳圈与名次。平台每两小时左右一场，单靠排行榜很难区分是哪项改动起了作用。

## 6. 风险

- 提高利用率必然增加失控风险。第19场在Highland发卡弯出过单车事故；第一步只到约70%，保留V4/V5的偏离恢复、滑动限油门和低速保护。
- 99.5分位上限里包含失控车辆，所以先用70%，再看滑动时间占比、离线距离和damage事件后逐步上调。
- 这些都是基于公开回放的离线结论，新版本的效果仍要靠新的平台对局验证。

## 7. 复现

```sh
python tools/replay_analysis.py history  --out replays
python tools/replay_analysis.py download --out replays --me <你的显示名> --last 20
python tools/replay_analysis.py summary  --out replays --me <你的显示名>
python tools/replay_analysis.py envelope --out replays --me <你的显示名>
python tools/replay_analysis.py corners  --out replays --me <你的显示名>
python tools/replay_analysis.py lapsplit --out replays --me <你的显示名>
```

`replays/` 已加入 `.gitignore`。每场回放下载约25MB，解析后约11MB。
