# V4 修改理由与验证

本轮将 `agent/` 更新为 V4 候选。出发点是第 19 场 Highland 的单车越界损坏，以及限速和油门控制问题。用户要求适度积极、以完赛为优先；这一目标不能转化为本地测试就保证每场正式完赛。

## 修改内容

| 部分 | V3 主版 | V4 候选与理由 |
|---|---|---|
| 当前位置弯度 | 用前方15/30m做线性外推 | 用公开地图按s插值，避免急弯前误限速和弯中提前解除限速 |
| 转向前馈 | 固定使用前方15m弯度 | 当前弯度加约0.10秒行驶距离的短提前量，最多4m；加入随车速变化的横向反馈，减少先切内再冲外 |
| 转弯半径 | 转向未对应实际偏移线修正 | 以k/(1−offset*k)修正转向；规划速度对实际/目标偏移取保守包络 |
| 制动规划 | 24个、每15m预览点，制动预算7×grip | 公开地图约2m采样，全圈反向传播制动约束，预算降到5.5×grip，提前温和制动并覆盖起终点接缝 |
| 横向预算 | 全弯10×grip | 急弯仍10；中弯11；缓弯12，依据曲率分段。均是候选策略预算，不是测得的真实轮胎极限 |
| 最高目标 | 55m/s=198km/h | 60m/s=216km/h；仍受前方弯道、湿度、磨损、交通和稳定状态限制，非全程目标 |
| 油门制动 | 只看当前速度误差 | 加入规划加速度、公开驱动力、质量、阻力和坡度；目标附近补偿维持速度所需的力 |
| 出弯加速 | 误差大时直接大油门 | 横向负荷越大，纵向加速预算越小；滑动时进一步减小正加速度，后轮滑动油门≤25% |
| 偏离恢复 | 横向偏离仍可能允许15m/s | 偏差越大越减速；靠近边界目标≤6m/s，较大航向误差降至10或5m/s，恢复时避免继续加油 |
| 超车入口 | 只检查前90m是否直 | 检查前150m，减少急弯前新发起超车；继续保留V3已提交超车车道与安全并回保护 |

原有湿度/磨损缩放、横向目标0.8m/s平移、转向动作变化率、发车车道、湿地起步保护、进站规则和动作接口保留。交通限速生效时不会叠加自由道路的加速度前馈。

`design.json` 与 V3 完全逐字节一致：本轮没有同时改翼角、齿比、油量、轮胎或悬挂。燃油储备偏大值得后续单独研究，但本场最直接的问题是控制缺陷，先让对照范围清晰。

## 地图与提交文件

仍然只上传根目录两个文件：`agent.py`、`design.json`。公开地图的曲率和坡度以数值常量嵌入 agent.py，保持约2m采样，不依赖本地绝对路径、仓库目录、网络或附带JSON地图。策略仅导入标准库 `math`。

- 曲率保留7位小数，坡度5位小数。
- 每张地图标注原始公开地图SHA256，`tools/embed_v4_maps.py` 可重新生成嵌入段。
- 按赛道坐标周期选择地图，并核对实时前3个预览弯度；长度或几何不匹配时进入45m/s上限的保守实时预览路径。
- 源文件约201KB，低于单文件256KiB要求；源文件合计、JSON和ZIP结构也由打包器检查。
- 不能在编辑代码时直接改嵌入地图数字；应改生成工具或公开输入后重新生成并验证。

## 已完成的验证

1. **88项单元/回归测试通过。** 原64项历史约束明确针对冻结V2/V3和V3独立试验版继续测试；新增24项直接导入当前V4，覆盖事故急弯、出弯当前弯度限制、偏移线、湿地、滑动、阻力/坡度补偿、进站、交通和边界。没有拿“旧版约束仍通过”冒充新版验证。
2. **第1–19文件夹共375,644条历史输入检查通过。** 导出原始决策行数量、字节数、SHA256全通过；V4所有输出字段、有限数值、范围、JSON类型和油门/刹车互斥均通过；进站自动驾驶的零踏板约定通过。375,644次地图检查全部匹配。
3. **本场代码归属核验。** 第19场20,192个原始动作与冻结V3主版一致，且程序fault为0。训练导出的bundle哈希不与单文件哈希混用。
4. **简化闭环敏感性测试。** 三图×干燥/湿度0.56/全湿×两组假设轮胎极限共18个单车整圈场景，均沿模型赛道走完且最小中心点至路边距离≥3.66m。另测最急弯、方向响应延迟及4个交通场景；交通场景可完成超越和并回，未触发所设矩形碰撞判定。
5. **本机计时。** 每份已记录输入上的V4动作计算累计约0.07–0.43秒，计时包括首次用到地图时的规划表构建，但不包括日志JSON解析。不同平台硬件和计费方式可能不同，这不是官方CPU测评。
6. **上传包检查。** 两个文件、语法、严格JSON、大小、ZIP CRC、文件字节和哈希检查；解压到独立临时目录也能导入并使用。

简化闭环不是官方SDK或AGX引擎。轮胎极限、方向延迟、力曲线和阻力等包含明示的测试假设，只用于筛查明显失稳；没有真实对手策略、损坏累积、轮胎/能量演化和进站引擎。不能从模型里的圈时推断正式圈时，也不能把历史输入上动作合法等同于新版本真的跑完历史比赛。18个测试场景全部走完，不代表正式比赛完赛率100%。

完整验证见 `analysis/v4-validation/validation.json`、`unit-tests.json`；第19场诊断见 [日志分析](第19场日志分析.md)。

## 本地复现

在具有NumPy的Python环境中运行分析和全部历史测试；提交车手本身不需要NumPy。

```sh
python -m unittest discover -s tests -v
python tools/validate_v4.py /path/to/Formula --output analysis/v4-validation
python tools/build_submission.py --output submission-v4.zip --manifest submission-v4.manifest.json
```

`baselines/v3/` 冻结本次前的已参赛主版；`baselines/v1/`、`baselines/v2/` 和 `experiments/v3-corner/` 保留。V3的构建及验证工具已改为引用冻结V3，避免未来生成所谓V3时误读当前V4。

## 平台验证与下一步

上传新的V4 ZIP，发布后确认报名使用V4。先以无损坏退出、稳定完成规定圈数为首要指标，再比较同图相近湿度下圈速、弯道速度和直线加速。建议每张地图都积累比赛，不用单场名次决定参数好坏；一旦仍有相同弯道越界，先查看真实n、航向和滑动，再决定继续提速。
