# V3 交通修复与独立弯道试验版：修改理由和验证

日期：2026-11-17。基于已参赛 V2（仓库提交 22b3d5f），开发分支 fix/v3-traffic。
按用户选择交付两个独立 ZIP：V3 主版只修交通和超车；弯道补油只在独立试验版中启用。

## 1. 为什么要修

V2 在 Formula/13–18 的六场中没有首圈损坏退赛，但第 14、18 场只完成两圈。历史逐帧诊断显示，交通限速分别覆盖约 84.1% 与 62.5% 的记录时长。此前发起超车只尝试固定 ±2.5 m，要求与前车大于 2.6 m，之后又用 2.8 m 判断是否继续受跟车限速。对居中慢车，这些条件不能一致满足。

之前的合法动作重放没有验证车手能否完成一次超车，是我上一版的测试缺口。本轮增加了正向超车反馈场景和相应危险反例，不再只检查返回字段。

## 2. V3 主版改动

|内容|V2|V3|
|---|---|---|
|候选车道|绝对位置 ±2.5 m|相对前车当前车道，向两侧各偏移 3.2 m|
|间距口径|选线 2.6 m、跟车 2.8 m 不一致|统一交通间距 2.8 m，并为目标额外留 0.4 m|
|速度保护解除|目标位置和实际位置经常仍在 2.8 m 内|目标可达到间距以外；只有实际位置和目标位置都达到间距后才解除对应前车约束|
|持续超车|直路条件一消失就丢弃超车目标|进行中的超车跨弯道保留侧线，由原弯速规划约束速度|
|短暂丢失目标|可能立即开始向中间回线|保持已选侧线最多 1 秒，避免单条观测缺失引起回摆|
|结束/放弃|状态切换与回线检查不足|目标落后超过 12 m、拉远至 65 m 或持续丢失后结束意图；回线仍需通道检查|
|通道预测时长|最多 3 秒|按剩余横移距离 / 0.8 m/s + 0.5 秒覆盖本次完整横移|

2.8、0.4 m 和 1 秒是本轮交通控制选择，不是官方车辆宽度或碰撞阈值。目标相对前车计算，因此偏离中心的前车也可处理；道路放不下候选时不把目标硬夹到前车身旁，而是放弃该侧。扫掠检查、9 m 纵向间隔判断和实际换线完成前的跟车制动仍保留。

不在急弯发起新超车。已经并行或正在绕行时保持侧线，可以避免一到弯道就向邻车横穿；原计划仍会按偏移线路收紧弯速。若前车继续拉远，结束尝试后也只在安全时回线。

## 3. 按要求保留的内容

主版的以下函数通过语法树逐项比较，与冻结 V2 完全一致：clip、angle、grip_budget、plan_speed、pit_entry_distance，以及 Driver.choose_pit、Driver.road_bounds、Driver.act。

- 车辆设计书逐字节一致，燃油仍为 60 kg。
- 目标极速仍为 55 m/s，横向/制动预算仍为 10×grip、7×grip。
- 转向控制、油门/刹车公式、ERS 与气动选择、进站策略、起跑车道渐变、横移速率 0.8 m/s 均保留。
- 变更集中在交通几何、超车状态和通道预测。线路目标变化仍会通过原速度公式影响局部目标，解除慢车约束也会使油门自然增加；这属于交通修复的预期作用，不是额外提高转弯参数。

已参赛 V2 完整保存在 baselines/v2/。主版仍是仅导入标准库 math 的独立 agent.py，无地图权重或本地 SDK 依赖。

## 4. 独立弯道试验版

experiments/v3-corner/agent.py 由 V3 主版和 experiments/corner_support.py 自动生成，是可独立上传的单文件车手。

试验版只在原目标以下、没有刹车/跟车限制、车身稳定、恒定或放缓弯道且横向预算有余量时，用公开阻力和驱动力遥测计算小幅补油；具体门限、每张地图的弯段及日志证据见《三赛道弯道与油门分析》。

不会修改目标速度、车辆设计、转向、ERS 或气动动作。额外油门最多 0.15，并接近原目标时淡出；没有所需遥测时自动退回主版的油门。它是待实测的控制假设，不是已经证明能提升弯速的版本。

## 5. 已完成验证

### 回归测试

共 64 项通过，包括原有测试、非交通参数冻结检查和以下新案例：

- 居中慢车和偏离中心的慢车都有几何可用路线。
- 一侧占道时选择另一侧；两侧占道或道路太窄时不强行超车。
- 仅有换线意图时保留制动保护；实际横向间距足够后才允许恢复道路目标速度。
- 弯道到来、目标短暂消失不引起立即回线；快速后车能阻止危险并线。
- 预测时长覆盖新的横移距离；前车拉远后可以安全放弃。
- 补油试验在刹车、收紧弯、滑动、横向负荷过高、拥堵、低油量等条件下不增加油门。

### 简化反馈场景

将动作反馈给明确声明假设的简化自行车/交通模型：居中慢车、缓弯、初始短跟车距离，以及公开地图最窄 5 m 半宽场景。V3 完成了绕过慢车与安全回线，未触发测试定义的矩形接触；冻结 V2 在相同居中慢车场景未完成超车。

模型的加速度、转向滞后、车长车宽是测试设定，未标定为 AGX 物理。它证明状态机可在反馈循环中完成动作，不能用来声称实赛绝对安全、圈速或名次提升。

### 历史观测检查

对 Formula/1–18 全部 355,452 次决策检查，两版都通过字段、类型、有限数、范围和序列化检查，没有同时给正油门和正刹车；同时按各局实际版本核对 V1/V2 原动作及导出完整性。

其中 107,138 次排位输入上，V3 主版动作与冻结 V2 逐条相同，进一步确认主版未改自由驾驶逻辑。

试验版和主版逐条比较：除油门外所有动作、道路目标速度与横向目标都相同；只在满足门限时增加不超过 0.15 的油门。本批旧输入中共 6,679 条出现额外油门，不代表真实新对局将触发同样次数。

主版 act 在本机这批输入上的累计 CPU 约 7.871 秒（18 份合计，仅函数调用计时），不包含平台 IPC 和机器差异，不能替代正式资源准入。

固定观测不会随新动作改变车辆位置，尤其不能把旧日志中的交通限速下降量当成修复后收益。比赛效果仍需新版本正式对局验证。

## 6. 打包与使用

两个 ZIP 根目录都仅包含 agent.py、design.json，不包含日志、地图 JSON、测试、报告或工具。已检查 CRC、源码语法、JSON、大小约束和与各自源码逐字节相同；哈希见对应 manifest。

建议先上传 submission-v3-main.zip，准入通过后选择该版本参赛。先检查几场新的碰撞、超车、圈数和成绩认定状态；再单独上传 submission-v3-corner-experimental.zip 比较弯道补油，分别记录平台版本 ID，不混用两版比赛结果。

优先比较原第 14、16、18 场类似的慢车场景；弯道试验则看无交通干扰路段，比较目标速度跟踪、轮滑、修正、制动次数与圈速。V3 主版的纯干地换胎仍须继续通过真实比赛核验。

## 7. 复现

在仓库根目录（Python 3.10+；分析脚本需 NumPy）：

```sh
python3 -m unittest discover -s tests -v
python3 tools/build_corner_experiment.py
python3 tools/validate_v3.py /Users/syeah/Downloads/Formula --max-folder 18 --output analysis/v3-validation
python3 tools/analyze_corners.py /Users/syeah/Downloads/Formula --output analysis/v3-corners
python3 tools/build_submission.py --output submission-v3-main.zip --manifest submission-v3-main.manifest.json
python3 tools/build_submission.py --agent-dir experiments/v3-corner --output submission-v3-corner-experimental.zip --manifest submission-v3-corner.manifest.json
```

analysis/v3-validation/ 保存验证记录；analysis/v3-corners/ 保存地图目录和分组证据。原始本人日志继续留在用户指定的 Formula 文件夹，未放入仓库或赛车 ZIP。
