# V5 修改理由与验证

日期：2026-11-18。V5以已参赛V4为基线，保留转向、地图、道路限速和失控保护，重点改进稳定直道与出弯加速，并新增提前识别套圈快车、安全让道与并回逻辑。车辆设计保持不变。

## 为什么要这样改

第20场Highland的30,655个原始动作与V4源码逐项一致，程序fault为0。V4没有再因越界或损坏退赛，正赛滑动时间占比从第19场的23.26%降至3.65%，说明上一轮路线与保护修复有效。

但V4正赛直道均速只有112.66km/h、弯道均速78.65km/h，最佳圈256.002秒，最终仍只完成2圈、unclassified。最高速度虽达到208.18km/h，短直道和出弯提速却跟不上；相近位置和湿度的样本也未显示整体直线改善。两场天气、交通不同，不能把全部圈速差归给某一项参数。

明确的代码瓶颈是：V4把正加速度上限设为 `5×grip×横向余量`。全湿时grip约0.55，即使几乎没有转向，上限也只有约2.75m/s²，计入磨损还会下降。只放宽最高速度不能解决这个问题。

第20场另有3条contact记录，涉及两段快车套圈遭遇。原交通逻辑主要处理本人追赶慢车，没有提前给已领先的快车规划空间。因此本轮同时补充套圈交通处理。

## 1. 只在稳定、低横向负荷时增加动力

V5没有统一抬高弯速、强制最低油门或取消湿地缩放，而是在V4原有力控制中按状态释放额外加速余量：

- 只有地图匹配、航向误差<0.10rad、横向跟踪误差<0.75m、靠近路线且前后轮均未滑动时，才允许新增动力。
- 横向负荷利用率≤0.40时，净加速度候选预算从 `5×grip` 逐步放宽到最多 `10×grip`；0.40–0.85之间平滑收回增量；≥0.85时完全回到V4的加速限制。
- 另限制用于推进的轮端力，预算为 `11×grip×横向余量`。上坡和空气阻力补偿也占用这个预算，避免“补偿阻力后实际轮端力过大”。若新预算算出的净加速度低于V4上限，则保留V4上限；本轮只在允许状态增加正加速度，不额外降低原有动力。
- 出弯后随着弯度和横向负荷降低，逐步释放动力；仍在急弯、打滑或纠偏时沿用V4。
- 打滑、明显偏离或地图不匹配后，需连续稳定至少0.75秒才恢复额外动力。
- 正赛前6秒、低油量、未知地图、缺少必要滑动标志、前车触发交通限速或已接近目标速度时，不启用这项增量。

全湿、低横向负荷时，新净加速度候选上限约5.5m/s²；它仍会受到阻力、坡度、轮端力、轮胎磨损和动力可用量限制，并不保证实际一直达到5.5。V4在滑动时的正加速度限制与后轮滑动油门≤25%保留。

目标速度与负加速度控制保持原样；在相同观测、目标和模式下，V5没有提高制动阈值，也没有放宽急弯限速。更大正加速度仍需要新实战验证轮胎、能源和完赛表现。

## 2. 快车套圈：提前识别，空间足够才移动

只根据本人合法观测中的对手圈数、相对距离、速度、横向位置及短期历史进行判断：

1. **识别真实套圈关系。** 将圈数、沿赛道位置和环绕距离一起使用；起终点附近即使双方显示相同圈数，也可能已形成套圈关系。缺少对手圈数时不凭速度猜测。
2. **提前观察。** 关注后方400m内、相对接近速度>2m/s、按当前速度估算14秒内可能追上的领先车辆。先观察至少0.25秒横向移动，再选择让道侧。
3. **只在有足够直线、宽度和时间时开始让道。** 保留0.8m/s的目标车道变化率；候选车道需与快车预计路径保持约3.2m间隔。检查整个变道过程中的前后车、预测接近和横向漂移，以及前方路宽与弯道。时间不足或任意一侧被占用，就不强行切线。
4. **快车已贴近或正在过弯时保持路线。** 不临时横切、不为了让道突然新增制动。已经有横向空间时保持这份空间；安全到侧方后，近距离通过阶段可暂时维持当前速度，让快车通过，原有道路制动仍然生效。
5. **通过后再安全并回。** 快车领先约20m后才结束专门让道；回到正常路线仍必须通过V4的扫掠检查。短暂失去对手可见信息时保持车道最多2秒，不立即并回。

新增横向预测只使用过去观测的平滑变化率，短期投影最多±1m；不是读取对手未来动作。对手主动改变路线、在弯中挤压或突然减速仍可能造成接触。该逻辑不能保证避免所有碰撞。

## 3. 明确保留的V4行为

以下核心函数通过语法树逐项比较，与冻结V4一致：

- 地图识别与插值、公开地图数值、全圈速度规划、湿度/磨损缩放；
- 当前弯度转向公式、航向/横向纠偏公式及转向变化率；
- 216km/h最高目标、横向预算、5.5×grip制动规划预算；
- 路边/偏离/大航向误差恢复限速、低油量限速；
- 进站及湿地规则处理、路宽余量、原有车辆扫掠安全检查。

车辆设计、翼角、齿比、初始燃油、轮胎和悬挂均未修改。`design.json`与V4逐字节相同。需要避让时请求车道会变化，因此实际转向动作可能与V4不同；这不等于修改了转向控制公式。

`baselines/v4/`保存实际参赛源码和设计，其agent.py的SHA256为 `b888ee5e2f379cfa0993261a374812e265ab525aebeb961a22d4e33d76750255`。V4历史验证和反馈工具明确读取该基线，避免把当前V5误当作V4。

## 4. 测试结果与局限

### 单元与行为回归

共128项通过：88项冻结历史/V4检查，加40项当前V5检查。新增覆盖稳定加速、弯中不增量、滑动恢复时间、低油量、未知地图、原制动行为、套圈圈数环绕、早/晚追近、两侧占用、预测横移、短暂消失、通过后并回以及慢车超车。

### 本人历史输入与导出核验

第1–20文件夹共406,299条输入：

- 原始导出行数量、字节数、SHA256及结尾完成标志全部通过；
- V5输出字段、JSON原生类型、有限数值、合法范围、油门/刹车互斥、维修区零踏板约定全部通过；
- 公开地图全部匹配；120,506条排位输入上，V5转向与道路目标和V4一致；
- 第20场30,655个原始动作与冻结V4一致，确认比较基线真实。

V5在第20场旧输入上能提前进入套圈观察与让道状态。但这些位置仍由V4产生，不能把它称作“V5已避免第20场碰撞”，也不能据此计算新圈速。

### 闭环与敏感性场景

以下均为明示假设的本地近似模型，不是AGX SDK：

- 三图×干燥/湿度0.56/全湿×两组假设横向极限，共18个单车整圈场景；另6个最急弯方向延迟场景，均保留所设几何安全余量。
- 18个直线加速场景，覆盖三档湿度、下坡/平路/上坡及两组假设牵引极限；V5响应均比V4更快，未触发模型所设后轮滑动阈值。
- 6个套圈闭环场景，覆盖干湿路面、窄路、一侧占用和可见的对手横移；完成让道、通过和并回，未触发所设矩形接触判定。
- 4个原有慢车超越反馈场景继续通过。

例如，平路阶跃模型以100km/h起步、控制目标设为163.6km/h，记录首次达到160km/h的时间：

| 条件 | V4模型响应 | V5模型响应 |
|---|---:|---:|
| 干地 | 3.63s | 2.27s |
| 湿度0.56 | 4.63s | 2.70s |
| 全湿 | 6.13s | 3.50s |

这些数值只说明在该力模型中新的加速限制确实释放了动力，不是正式比赛加速预测。模型使用选择的轮胎极限、力曲线、阻力、响应延迟和对手轨迹；没有完整AGX动力学、损坏累积、能源/轮胎演化或真实对手策略。正式圈速、碰撞率和完赛能力仍需新平台对局检验。

完整证据见 `analysis/v5-validation/validation.json`、`unit-tests.json` 和 `recorded20-lapping-intent.json`。

## 5. 上传与复现

上传ZIP根目录仍仅含 `agent.py`、`design.json`。策略只导入标准库math，公开地图曲率/坡度已嵌入代码；不依赖本地文件夹、SDK、网络或分析工具。

```sh
python -m unittest discover -s tests -v
python tools/validate_v5.py /path/to/Formula --output analysis/v5-validation
python tools/build_submission.py --output submission-v5.zip --manifest submission-v5.manifest.json
```

分析及部分历史测试需要NumPy；提交车手本身不需要。当前地图嵌入段由 `tools/embed_maps.py` 生成，车手源文件低于256KiB限制。

上传V5 ZIP、发布后确认报名版本已切换。下一场优先检查：排位是否有效完成、稳定直道/出弯加速、滑动占比、原急弯横向轨迹、套圈接触，以及正赛是否真正完成规定圈数。`running`或到截止才停止不等于完赛。

本轮保留V4弯道与制动限制，因此不会用盲目提高弯速来换取圈速。若新实战仍因限时未完成，再据同地图、相近湿度的日志定位剩余制动区或速度规划瓶颈。本地验证不能承诺每场完赛，也不等同于已在AGX发布。
