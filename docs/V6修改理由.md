# V6 修改理由与验证

日期：2026-11-19。V6以V5（已冻结在 `baselines/v5/`）为基础，只做《V5实战复盘与改进方案》里的第1步：把过弯、制动、加速和最高速度这几个限制，从保守猜测改为公开回放实测上限的约70%。车辆设计、ERS/低阻模式、行车线、交通和进站逻辑都不变（这些留到后续步骤）。

## 1. 为什么改

最近21场公开回放显示，V5只用了车辆约40–50%的能力：干地过弯约1.1g（场上能到约2.5g），制动约0.6g（场上2.6–3.0g），最高216km/h被代码写死（场上300–340km/h），稳定直道也几乎从不全油门。结果单圈比冠军慢34%–62%，几乎每场只能跑3圈。详见 `docs/V5实战复盘与改进方案.md`。

## 2. 改了什么

| 项目 | V5 | V6 | 依据 |
|---|---|---|---|
| 过弯预算 `lateral_budget` | 10 / 11 / 12 m/s² | 发卡弯（半径<20m）13，其他17 | 全场干地上限约24.5m/s²；无事故的前三名在弯中的90分位为17.2 |
| 制动预算 `BRAKING_BUDGET` | 5.5 m/s² | 14 m/s² | 全场干地制动上限约25–29m/s² |
| 制动执行下限 | −8×grip | −(14+4)×grip | 让控制器能执行速度表里的制动 |
| 最高速度 `TOP_SPEED` | 60 m/s（216km/h） | 90 m/s（324km/h） | 全场最高约92m/s |
| 正加速度预算 | 5×grip（V5条件放宽到10） | 12×grip，按横向负荷收回 | 全场净加速度约1.5g（低速） |
| 稳定直道全油门 | 无（按力换算，油门中位数20–35%） | 低于目标2m/s以上、横向负荷<50%、航向/路线稳定、无滑动时给1.0 | 冠军单圈30–70%时间全油门 |
| 湿地抓地损失 `WET_GRIP_LOSS` | 0.45 | **0.55** | 见第3节 |
| 在线抓地信任 | 无 | 新增，见第4节 | 防止实际抓地比计划低 |

`grip_budget` 仍然同时缩放过弯、制动和加速预算，所以湿度和轮胎磨损会自动降低所有目标。

## 3. 湿地比复盘方案更保守

复盘方案原计划沿用V5的湿地系数0.45。实现后，我把V6计划的每个弯的最低速度，与这21场里**无事故车辆**的实际弯中最低速度逐一比较（`analysis/v6-validation/corner-check.json`）：

- 干地：V6计划速度不超过任何一个弯里最快的无事故圈。
- 大雨（湿度≥0.75），系数0.45时：Crossover有9/16个弯、Highland有7/15个弯，**没有任何一辆无事故车**达到过V6的计划速度。

因此V6把湿地抓地损失提高到0.55（全湿时抓地按0.45计）。之后，全部三图干湿共76个弯里，只有4个弯的计划速度比最快无事故圈高，且都不到1km/h。代价是大雨中的提速比原计划少，但大多数比赛是湿地，宁可在这里留余量。

## 4. 在线抓地信任（新安全网）

如果某场实际抓地比计划低（轮胎、温度、天气变化），只靠固定参数可能会冲出赛道。V6新增一个0.70–1.00的抓地信任系数：

- 过弯中（|g_lat|>0.5g）或制动中出现前轮滑动、后轮滑动时，以每秒0.15的速度降低；
- 不滑动时，以每秒0.01的速度恢复，即降低0.15后约15秒恢复；
- 纯直线加速时的后轮打滑不计入（已有“后轮滑动时油门≤0.25”处理）；
- 每个阶段（排位/正赛）开始时、以及 `init()` 时重置为1.0。

所有速度目标和预算都乘上这个系数。诊断字段 `grip_scale` 可以在日志中看到它的变化。

## 5. 保留不变

AST逐项比较，以下与V5完全相同：`map_state`、`steer_command`、`plan_speed`、交通/超车/套圈让道全部方法、进站选择、路宽余量、扫掠安全检查、地图数据。另外保留：偏离>1.5m、航向>0.30/0.60rad、贴近路边、低油量这些限速，后轮滑动时限油门，起步前6秒湿地限油门，以及维修区零踏板。未知地图时仍用V5的保守回退路径（单独常量 `FALLBACK_BRAKING = 5.5`）。

回放显示实际转向几乎就是几何关系（转角 ≈ 3.4m × 路径曲率，0.2g到2.6g之间只偏大1–4%），所以V5的转向前馈在更高弯速下仍然适用，不需要改。

## 6. 验证

### 6.1 单元与回归：148项通过

- 128项历史测试：V5专项测试改为读取冻结的 `baselines/v5/`，与V4、V3同样处理。
- 20项新的V6测试（`tests/test_control_v6.py`）：
  - 动作字段、类型和范围（3图×40位置×4速度×3湿度）；只依赖标准库；设计未变；
  - 保留函数的AST一致；未知地图回退、维修区、各项恢复限速；
  - 全圈每个采样点V6目标不低于V5，且不超过324km/h；
  - 全油门的触发条件，以及滑动、偏离、低油量、弯中负荷、湿地低速、接近目标时都不触发；
  - 制动比V5强，且不超过执行下限；
  - 抓地信任的降低、恢复、下限、重置，以及直线打滑不触发；
  - 每个弯的计划速度不超过回放中最快无事故圈+1.5km/h；
  - 标定模型的整圈和湿地起步测试（见下）。

### 6.2 回放标定的整圈模型

`tools/feedback_v6.py` 是自行车模型，转向几何、抓地/制动上限、功率曲线、阻力和质量都从回放标定（不是平台引擎）。在这个模型里，V5的单圈比它的实战最佳圈约快5–8%，可以作为版本间比较的参照。

| 赛道 | 干地 V5→V6 | 湿度0.5 V5→V6 | 全湿 V5→V6 |
|---|---:|---:|---:|
| Parkland | 140.8 → 105.1s | 155.1 → 117.8s | 180.2 → 149.1s |
| Highland | 183.0 → 140.4s | 205.4 → 160.3s | 242.5 → 205.1s |
| Crossover | 161.1 → 123.3s | 180.4 → 141.0s | 212.1 → 178.8s |

（名义标定情况；悲观情况为抓地/制动约为实测的80%、转向延迟0.20s，结果相近，见 `analysis/v6-validation/model-laps.txt`。）

作为参照，最近21场冠军的最佳圈：Parkland 93–120s，Highland 138–184s，Crossover 120–155s。

- 全部36个模型场景都跑完整圈，离路边至少4.6m，滑动时间≤3.7%。
- 三图、两侧发车位的湿地起步都安全。
- 压力测试（`analysis/v6-validation/low-grip-stress.txt`）：模型抓地设为13–15m/s²，**低于V6的计划值**。12个场景中11个仍留在路面，唯一失败的是干地Crossover、抓地仅13m/s²（约为实测上限的一半）。
- 已知模型局限：Highland排位起点（s≈6579，22m/s，正处在发卡弯里）全湿时，V5和V6在模型中都会冲出。V4在第20场实战中通过了这里，说明是模型初始状态的问题，不是V6新引入的问题。

## 7. 风险，以及上线后看什么

- 这是一次大幅提速。模型和回放证据都支持，但平台的真实轮胎、路肩、碰撞和交通都没有完整建模，**完赛与否要看新对局**。
- 车快了以后会更常追上慢车。交通逻辑仍是V5的，超车条件偏严，可能在慢车后面跟一段；这属于第3步。
- 上线后优先看：①有没有damage退赛和离线事件；②诊断里 `grip_scale` 是否经常降到0.85以下（说明实际抓地比计划低）；③每圈时间与冠军的差距；④是否跑满4圈；⑤Highland排位是否有效。可以用 `python tools/replay_analysis.py summary --out replays --me <显示名>` 直接看。
- 如果出现单车失控：先把 `lateral_budget` 17 → 15、`BRAKING_BUDGET` 14 → 11，不要整体退回V5。
